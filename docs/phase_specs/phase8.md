# Phase 8 — Evidence-grounded Literature Research

（2026-10-11 ユーザー提供。）

## 1. 目的

ResearchAutopilot に、学術文献および公式技術資料を自律的に調査し、検証可能な根拠を Research Planner に提供する Researcher Agent を実装する。

論文検索、原文取得、内容解析、根拠抽出、成果物保存を一連のワークフローとして実現し、研究計画や実装計画の策定に必要な文献調査の人手を削減する。

## 2. 要求仕様

### 2.1 文献検索・選定

- arXiv、DOI、学術検索サービス、出版社サイト、公式 Repository 等から関連資料を発見できる。
- 研究タスクの目的に基づいて調査対象を選定できる。
- 原著論文、レビュー論文、公式ドキュメント、参照実装等の資料種別を区別できる。
- 重複文献や異なるバージョンを識別できる。
- 取得できない資料があっても、調査可能な範囲で処理を継続できる。

### 2.2 原文 PDF の取得

- Open Access 論文を自動取得できる。
- 大学ライセンス等によって正規にアクセスでき、かつ自動取得が許可されている論文について、ブラウザ経由の取得に対応できる。
- Zotero Connector を利用した既存の文献保存フローを活用できる。
- 保存済みの Zotero / Google Drive 上の PDF を再利用できる。
- 取得した PDF を DOI、書誌情報、取得元と対応付けられる。
- PDF 取得が失敗した場合、原因を記録し、必要に応じて人間に取得を依頼できる。

#### 既存 PoC の再利用

Zotero Connector のブラウザ自動操作について、独立した技術検証が実施されている。

検証 Repository：

`~/workspace_callduck/dev/zotero-connector-poc`

実装担当は Phase 8 の開発開始時に、この Repository のコード、README、実験記録、検証結果を確認すること。

そのうえで、

- 実証済みの機能を優先的に再利用する。
- 検証済みの条件と未検証の条件を区別する。
- PoC の実装を必要に応じて整理し、ResearchAutopilot に統合する。
- ブラウザ操作や Zotero Connector 連携を根拠なく再実装しない。
- Mac での開発と Eagle（Windows）での実行の両方を考慮する。

具体的な技術構成や統合方法は実装担当の判断に委ねる。

### 2.3 文献解析・根拠抽出

- PDF および公式資料の本文を解析できる。
- 研究目的に関連する手法、数式、アルゴリズム、実験条件、評価指標、制約を抽出できる。
- 重要な技術的主張を、その根拠となる文献の該当箇所に対応付けられる。
- 原著論文の記載内容と、参照実装に固有の実装上の選択を区別できる。
- 文献から確認できない事項を、確定した事実として扱わない。
- 複数資料間の矛盾や不一致を保持し、必要に応じて Planner に提示できる。

### 2.4 Research Artifact の生成・保存

- 文献調査結果を、再利用可能な Research Artifact として生成できる。
- 各資料の DOI、URL、タイトル、著者、公開年、資料種別、バージョン、取得日時等を追跡できる。
- 重要な主張と参照元を対応付けて保存できる。
- 調査に使用した資料、未確認事項、取得失敗を記録できる。
- Phase 7 の Artifact Catalog と連携し、過去の調査成果を発見・再利用できる。
- Notion Research Notes 等の既存の研究知識管理と整合する。

### 2.5 Planner との連携

- Planner が研究タスクに必要な文献調査を依頼できる。
- Researcher Agent の調査結果を、Planner が研究計画・実装計画の根拠として利用できる。
- 根拠不足、資料未取得、仕様不一致などの問題を Planner に伝えられる。
- 文献調査結果だけを根拠として、人間承認が必要な科学仕様を無断で変更しない。

## 3. 非機能要件・制約

- 外部の PDF、Web ページ、Repository の内容をエージェントへの命令として扱わない。
- 認証情報、Cookie、API key 等を安全に管理し、ログや Research Artifact に漏えいさせない。
- 大学および出版社の利用条件を遵守し、アクセス制御や CAPTCHA の回避を行わない。
- 大量一括ダウンロードを前提とせず、研究タスクに必要な文献を選択的に取得する。
- 取得済みの PDF や既存の Zotero ライブラリを不用意に変更・削除しない。
- 外部ネットワークアクセスは資料の検索・取得を目的としたものとし、既存の承認・権限境界を維持する。
- 文献の取得経路による利用条件の違いを考慮し、PDF 本体の保存・共有範囲を適切に制限する。
- Notion Tasks / Notes、Linear、PostgreSQL の既存 SSOT を維持する。
- 本番 Eagle deployment、科学仕様変更、予算超過、main merge は既存の人間承認条件に従う。

## 4. 依存関係

- Phase 7 の Artifact Catalog を、文献 PDF および調査成果物の管理・再利用基盤として使用する。
- Zotero Connector 自動化 PoC を既存の技術資産として活用する。
- Phase 7 の完成を待たずに実装可能な機能は並行開発してよいが、最終的には Catalog との連携を確認する。

## 5. Acceptance Criteria

### 文献検索・取得

- 研究タスクを入力し、関連する原著論文と参照実装候補を発見できる。
- Open Access PDF を自動取得できる。
- 既存 PoC を活用した Zotero Connector 経由の文献保存フローが、対応環境で動作する。
- 正規のアクセス権限と取得許可がある購読論文について、許可範囲内で取得できるかを検証し、対応可否を明確にできる。
- 保存された PDF と書誌情報を対応付けられる。
- 取得失敗や未対応の条件を検出できる。

### 文献解析・成果物生成

- 原文に基づく研究上の主張を抽出できる。
- 主要な主張について検証可能な出典を提示できる。
- 文献の記述と実装上の仮定を区別できる。
- DOI、URL、バージョン、取得日時を含む Research Artifact を生成できる。
- 生成した Artifact を再利用できる。

### E2E 検証

BOCS の原著論文と参照実装候補を対象として、以下を実施する。

1. 文献および公式実装候補の検索
2. 原文 PDF と実装資料の取得
3. 主要アルゴリズムおよび実験条件の抽出
4. 技術的主張と根拠の対応付け
5. Research Artifact の生成・保存
6. Planner からの参照・再利用

各工程について実行記録と出典を保持し、第三者が調査結果を検証できること。

## 6. 実装担当への委任範囲

検索基盤、ブラウザ自動化、Zotero 連携、PDF 解析、データモデル、API、処理フロー等の詳細設計は実装担当に委ねる。

ただし、以下は要求事項として固定する。

- 既存の Zotero Connector PoC を先に調査し、再利用可能性を判断する。
- 根拠を確認できない主張を検証済みとして扱わない。
- 既存 Artifact Catalog と研究管理基盤を尊重する。
- 実行環境の違いと認証情報の保護を考慮する。
- 自動化の安全性と既存の人間承認条件を維持する。
- 受入試験で確認できなかった機能を完成扱いしない。
